## Overview:
Modern Machine Learning is shaped by the hardware used under the hood. It ranges from role-specific hardware such as NPU(Neural Processing Unit), LPU(Language Processing Unit), DPU(Data Processing Unit) to Core ML processors such as CPU, TPU and GPU. CPU, the brain of the computer is present in all the computers, primarily focused on the processing complex tasks. On the other hand GPU, are known for performing multiple small tasks parallelly in order to accomplish a task much faster than a CPU could ever do. ML models are repeatedly trained on huge datasets, so that they recognise the pattern hidden under the data. Model training can last from minutes to days, based on the size of the model and the dataset. Hence, GPU programming can help in improvising model training and save time. This was my motivation behind learning GPU Programming. This article, is my exploration on GPU programming so far, and a detailed walkthrough on programming for matrix addition using `triton`.

## CPU vs GPU
CPU - Central Processing Unit is a part of all the computers, as mentioned earlier. They consists of Control Unit(CU) to understand what operation is required. Arithmetic Logic Unit(ALU) to handle mathematical and logical operations. Registers, the high-speed, low-capacity storage cells located directly on the CPU chip used to hold temporary data and instructions during execution.\
![CPU Architectural Diagram]({{'assets/images/cpu_architectural_diagram.jpg'|relative_url}})\
Due to this arrangement, CPUs are better at performing complex single task at a time. For executing multiple tasks at a time, CPU uses context switching to achieve concurrency[(ref)](https://www.youtube.com/watch?v=RlM9AfWf1WU). In order to achieve parallel programming, there needs to be multiple CPU cores stacked together, performing one task each. This is where GPUs work differently and can run multiple tasks at a time. \
GPU - Graphical Processing unit accelerates tasks like rendering of images, animations etc by performing massive number of computations in parallel. GPU contain Processing Cores, which in turn contains several Graphics Processing Clusters(GPC). Each GPC has several Streaming Multiprocessors(SM). Each SM contains several warps and ray tracing cores. A warp is 32 threads scheduled together, which runs on shader cores and tensor core. Shader cores are used for binary calculation, consisting of arithmetic operators. Tensor Cores are the matrix multiplication and addition calculators. Ray Tracing cores are for executing ray tracing algorithms used in graphic designing[(ref)](https://www.youtube.com/watch?v=h9Z4oGN89MU).\
![GPU Architectural Diagram]({{'assets/images/Basic-GPU-architecture.png'|relative_url}})

## GPU Programming languages:
There are three GPU programming languages I am currently aware of: CUDA, Triton and Jax.
`cuda c++` is a extension of the standard `c++` language. `Triton` is an open-source python library created by OpenAI for GPU Programming, and `jax` is a high-performance Python library for array-oriented numerical computing and machine learning research. `jax` uses XLA, which help accelerate the performance of operations on GPUs. Whereas `cuda` and `triton` are kernel-level programming languages, where we manage the data movement and memory allocation.\
In the next section, I will walkthrough a problem statement and solve it in `triton`.

## Walkthrough of a problem:
**Problem Statement** [(link)](https://leetgpu.com/challenges/matrix-addition)\
Implement a program that performs element-wise addition of two `N X N` matrices containing 32-bit floating point numbers on a GPU. The program should take two input matrices of equal dimensions and produce a single output matrix containing their element-wise sum.\
Implementation Requirements:
- External libraries are not permitted
- The solve function signature must remain unchanged
- The final result must be stored in matrix C

**Solution in Triton** [(link)](https://github.com/mlscmoulika/gpu_testing)
```python
import torch
import triton
import triton.language as tl


@triton.jit
def matrix_add_kernel(A, B, C, N, BLOCK_SIZE: tl.constexpr):
    pid_0 = tl.program_id(0)
    pid_1 = tl.program_id(1)

    r = pid_0*BLOCK_SIZE+tl.arange(0,BLOCK_SIZE)
    c = pid_1*BLOCK_SIZE+tl.arange(0,BLOCK_SIZE)

    a = tl.load(A + r[:, None]*N+c[None, :], mask=(r[:,None]<N)&(c[None, :]<N))
    b = tl.load(B+ r[:, None]*N+c[None, :], mask=(r[:,None]<N)&(c[None, :]<N))

    c_ans=a+b 
    tl.store(C+r[:, None]*N+c[None, :], c_ans, mask=(r[:,None]<N)&(c[None, :]<N))
    


# a, b, c are tensors on the GPU
def solve(a: torch.Tensor, b: torch.Tensor, c: torch.Tensor, N: int):
    BLOCK_SIZE = 64
    
    grid = (triton.cdiv(N, BLOCK_SIZE),triton.cdiv(N, BLOCK_SIZE))
    matrix_add_kernel[grid](a, b, c, N, BLOCK_SIZE)
```
Before giving you a walkthrough of the code above, I would like to walk you through the how I think when solving a problem using `triton`.\
I think of the following things:
- **How many pointers do I need?**- When dealing with huge sized matrix, in triton we use tiling to pick a part of the matrix on which we need to perform the operation and the other parts are taken care of using parallel processing. During parallel processing it is important how we want to control how we are going to access the data from the server. Hence the number of pointers is important. Here in this case we need two pointers, one to track the values of rows and another to track values in column. 
``` python
grid = (triton.cdiv(N, BLOCK_SIZE),triton.cdiv(N, BLOCK_SIZE))
matrix_add_kernel[grid](a, b, c, N, BLOCK_SIZE)
```
``` python
pid_0 = tl.program_id(0)
pid_1 = tl.program_id(1)
```
- **How can I access the values from Matrix?** - The way matrices are accessed from the memory is based on how you want to perform operations and on which elements. The whole matrix is flattened and stored. Hence if you want to extract a grid from the matrix it won't be straight-forward. Hence after calling the pointers, we need to determine what portion of the row and column do we need to extract. And as mentioned before about 'tiling', we need to pick the elements based on the grid size, or in this case the `BLOCK_SIZE`.
```python
r = pid_0*BLOCK_SIZE+tl.arange(0,BLOCK_SIZE)
c = pid_1*BLOCK_SIZE+tl.arange(0,BLOCK_SIZE)
```
The above code, get the pointers for the row(`r`) and column(`c`)  elements based on `pid_0` and `pid_1`. 
Time to load the elements now
```python
a = tl.load(A + r[:, None]*N+c[None, :], mask=(r[:,None]<N)&(c[None, :]<N))
b = tl.load(B+ r[:, None]*N+c[None, :], mask=(r[:,None]<N)&(c[None, :]<N))
```
`A` is the pointer to matrix `A`, and `r[:,None]` is going to create 2D matrix and so does `c[None,:]`. Assume that the `BLOCK_SIZE` is 2. In ther first iteration. `r` would have `[0, 1]` and `c` would have `[0,1]`. And `r[:, None]` would be `[[0], [1]]`. `c[None, :]` would be `[0, 1]`. If we added these matrices as it is without multiplying with `N`. After broadcasting, we will end up with `[[0, 1], [1, 2]]`. However, if you think of the whole matrix. Assume that we have `A`, as a 3\*3 matrix. The first 2\*2 matrix grid would look like, `[[0, 1], [3, 4]]`. If we multiply the matrix `r[:, None]` with `N`, and adding with `c[None, :]` that is exactly what we end up with(`r[:, None]*N + c[None, :]`). The mask is to avoid going out of range in the array.
- **What is the core operation?**- Here since it is matrix addition, the core operation is adding `a` and `b`.
```python
c_ans=a+b 
tl.store(C+r[:, None]*N+c[None, :], c_ans, mask=(r[:,None]<N)&(c[None, :]<N))
```
Then we store the result using the same logic that we use for extraction and store the values from `c_ans` to matrix, `C`.
